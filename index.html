Case file 1

The test that failed for the wrong reason

The situation

UI automation has a classic trap: a script clicks before the page has finished loading, fails, and everyone blames the product. I built around that from day one on an e-commerce demo site.

What I did

I stopped telling the test when to move and told it what to wait for. Explicit waits make every step patient. The Page Object Model gives each page one home, so a changed button means one edit, not twenty. The URL and browser live in config.properties, so the same suite runs anywhere with a one-line change.

The outcome

Seven positive and negative cases cover login, add to cart and checkout. Every run ends with a timestamped ExtentReports page and screenshots, so a failure is a real finding, not noise.

Case file 2

One booking flow, many passengers

The situation

A flight booking is one journey with endless variations: different routes, different passengers. Copy-pasting a test for each one would turn the suite into a maintenance problem.

What I did

I wrote the journey once (search, reserve, purchase, confirm) and let Excel drive it. TestNG Data Providers read each row through Apache POI, and the same test runs once per booking. Smoke and functional groups mean a quick check does not need the full run, and a screenshot utility captures the screen the moment something fails.

The outcome

Adding a new booking is one new row in a spreadsheet. The test code stays untouched.

Case file 3

The API suite that could only run once

The situation

API tests have a quiet habit: they pass the first time and fail the second, because the user they created already exists. They also lean on each other, since logging in produces the token every later call needs.

What I did

Each run builds a fresh email from a timestamp, so the suite can re-run forever without cleanup. The bearer token and contact ID travel from one test to the next, from registration to logout. RestAssured and Hamcrest check status codes, status lines and response bodies. A matching Postman collection (Chai assertions, collection variables, pre-request scripts) lets anyone run the same flow without writing code.

The outcome

Ten tests across POST, GET, PUT and PATCH run end to end and finish with an ExtentReports HTML report.
